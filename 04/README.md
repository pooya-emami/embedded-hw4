# Part 4: SNMP Sensor Reading

## Project Overview
Part 4 adds **SNMP support** to the distributed sensor system.  
The Master node exposes sensor information through **custom SNMP OIDs**, and clients can read sensor values using `snmpwalk` or `snmpget`.

The SNMP service runs only on the Master node.  
Slave nodes are not queried directly; instead, SNMP uses the Master’s Part 3 API to retrieve the latest sensor values.

---

## System Architecture

### Components
```
Client (snmpwalk/snmpget)
        ↓
snmpd (Master)
        ↓
pass directive → sensor_pass.sh
        ↓
Part 3 API (HTTP)
        ↓
Master DB / Cache / Slave fallback
```

### Data Flow
1. Client sends SNMP request.  
2. `snmpd` receives the OID.  
3. `snmpd` forwards the OID to `sensor_pass.sh` using the `pass` directive.  
4. The script calls the Master API (`/query`) to fetch the sensor value.  
5. The script prints the result in SNMP format.  
6. `snmpd` returns the result to the client.

## SNMP Configuration

### config.example
This file defines:
- Master IP  
- Master API port  
- SNMP port  
- All sensors exposed via SNMP  

Example:
```
MASTER_IP=192.168.233.139
MASTER_API_PORT=8080
SNMP_PORT=1161

SENSOR=temperature,101,Floor1_Room101_Temp
SENSOR=humidity,102,Floor1_Room101_Humidity
...
```

### SNMP Setup (Master only)
```bash
cd 04/scripts
./setup_snmp.sh --run
```

This script:
- Generates `snmpd_master.conf`  
- Adds the `pass` directive  
- Points SNMP to `sensor_pass.sh`  
- Starts `snmpd` on the configured port

## Custom OID Structure

All sensors are mapped under:

```
iso.3.6.1.4.1.99999.1.<sensor_id>.<field>
```

Where `<field>` is:

| Field | Meaning |
|-------|---------|
| 1 | sensor name |
| 2 | sensor type |
| 3 | latest value |
| 4 | unit |
| 5 | timestamp |

Example for sensor 101:

```
iso.3.6.1.4.1.99999.1.101.1 → "Floor1_Room101_Temp"
iso.3.6.1.4.1.99999.1.101.2 → "temperature"
iso.3.6.1.4.1.99999.1.101.3 → "24.8"
iso.3.6.1.4.1.99999.1.101.4 → "C"
iso.3.6.1.4.1.99999.1.101.5 → "2026-06-01 10:15:00"
```

## SNMP Configuration Details

### snmpd_master.conf (generated by setup script)
```
rocommunity public
pass .1.3.6.1.4.1.99999.1 /bin/bash <path>/sensor_pass.sh <API_URL> <config.example>
```

### sensor_pass.sh behavior
- Receives OID from SNMP  
- Parses sensor ID and field  
- Calls the Master API:  
  ```
  /query?sensor_type=<type>&sensor_id=<id>
  ```
- Extracts value, unit, timestamp  
- Prints SNMP‑formatted output


---

## Notes
- SNMP depends on the Part 3 API; if the API is not running, SNMP will return no values.  
- All OIDs are generated dynamically from `config.example`.  
- SNMP always returns the latest sensor value from the distributed system.
